# 业务规则

## 核心对象

### 人员与账号

- `people` 是责任人、业务角色和系统访问的统一主档。
- 业务角色为 `admin`、`handler`、`reviewer`。登录账号由可选的 `neon_auth_user_id` 关联 Neon Auth，不建立第二套人员。
- 登录标识为唯一邮箱；个人设置可改显示姓名、头像和密码，邮箱由管理员维护。
- 停用人员不能登录或作为有效业务人员；系统必须至少保留一个启用中的管理员。
- `reviewer` 可新增非管理员人员主档，但登录账号开通、管理员角色和既有人员维护仍由 `admin` 完成。

### 负债

- 负债品种目录以 `src/lib/debt-types.js` 为唯一代码配置，不建立目录表。
- 基类保存通用金额、利率和生命周期字段；品种表只保存真正专属字段。
- 浮动与固定收益凭证在数据后台合并为“收益凭证”，以 subtype 保留仪表盘筛选维度。
- `total_amount`、`term_days` 和状态由数据库计算，不允许页面自行写入。
- 所有本金、利息、费用和补充流统一为现金流，不建立品种专属 schedule。

### 融资项目与 SOP

- 融资项目独立于负债记录。项目创建、修改和删除不读取、绑定或修改存续负债。
- 项目维护名称、融资品种、规模、负责人、状态、说明和单一“计划簿记”日期。
- 创建项目时选择启用 SOP；计划簿记日写入 `planned_issue_date`，作为 SOP“计划发行当日”的相对日期锚点。
- 项目起始日由最早 SOP 节点自动推导，不再作为第二个人工计划日期。
- 删除项目时在一个事务中同步删除项目任务及其提醒记录；重复删除按幂等成功处理。
- SOP 节点顺序具有业务含义，拖拽排序必须作为一个原子动作提交。
- `reviewer` 可新建项目和 SOP 模板；项目后续维护、SOP 节点编排、模板启停和提醒规则仍由 `admin` 完成。
- 每个启用角色都可更新 `assignee_id` 等于本人 `personId` 的任务节点状态；任务负责人、截止日及他人节点不得随该动作变更。

### 提醒

- 提醒规则作用于由 SOP 节点生成的项目任务；一条规则可关联多个 SOP 节点。
- 一条规则支持 1–20 个提醒周期，每个周期用“提前 x 天 x 小时”表示。整天周期统一在对应日期 09:00（`Asia/Shanghai`）发送；包含小时的周期相对节点到期日 00:00 倒推，并在所得实际整点发送。
- 收件人可来自任务负责人、项目负责人或指定邮箱。
- 同一 `(rule_id, target_id, period_id)` 只发送一次，同日多个小时周期分别记录。
- Resend 未配置时记录 `pending`，不能标记为已发送。
- Provider 返回 `sent` 只表示接收请求，不等于邮件已投递到收件箱。

### 监管参数与额度

- `finance_parameters` 保存按期间维护的财务参数；`debt_limit_configs` 保存负债品种额度和计算模式。
- 金额数据库单位为元或字段明确规定的亿元；页面展示必须标示单位并保持同一视图小数位一致。

## 状态

- 项目：`planning`、`in_progress`、`at_risk`、`completed`、`cancelled`。
- 项目任务：`not_started`、`in_progress`、`blocked`、`completed`。
- 负债状态由生命周期日期生成：未生效、存续、到期、关闭；不得作为可写字段维护。
- 提醒发送：`pending`、`sent`、`failed`。

## 时间与交互不变量

- 业务“今天”按 `Asia/Shanghai` 解释。
- 甘特范围由今天、项目计划簿记日和节点日期共同决定，并扩展到完整月份。
- 有权限的项目、任务和 SOP 普通字段自动保存；创建、删除、启停、安全动作和数据后台逐行编辑显式保存。
- mutation 成功后只合并服务端确认的实体；失败时保留输入，不回滚到旧页面快照。

## 数据质量原则

- 财务数据必须区分数据错误、来源缺失和口径不明确。
- Excel 映射或统计口径变化必须对账数量、金额、日期范围、重复 ID 和孤儿引用。
- 不因某一个日期计算吻合就推断业务公式；先取得业务定义和字段口径。
